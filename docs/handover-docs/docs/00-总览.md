## 1. 这套能力解决什么问题

SSE 的数据分两处落地：

| 存储 | 引擎 | 物理位置 |
|---|---|---|
| 业务数据 | PostgreSQL 16 | Docker 卷 `sse_pgdata` → `PGDATA` |
| 附件对象 | MinIO | Docker 卷 `sse_miniodata` |

当**磁盘损坏、系统重装、版本回退、跨机迁移**时，需要把这两个存储里的数据
完整取出、验证、再放回系统。传统做法是"把旧盘挂上，起服务，数据还在就导出"。

本套能力提供的是**完全离线的路径**：

```
┌──────────────┐   不起任何服务    ┌──────────────┐   可离线搬运    ┌──────────────┐
│  旧盘 (只读) │ ────────────────▶ │  备份包      │ ──────────────▶ │  新系统      │
│  PGDATA      │   解析磁盘文件     │  CSV + 对象   │   校验后导入     │  PG + MinIO  │
│  MinIO 数据   │                   │  + 元数据     │                  │              │
└──────────────┘                   └──────────────┘                  └──────────────┘
      ↑ 一个字节都不改                  ↑ 自带 checksum                ↑ 自带回滚
```

**三条硬约束**（全程遵守）：

1. **旧盘零写入** —— 所有写操作只发生在副本和目标系统上。
2. **不起旧盘服务** —— 不启动旧 PostgreSQL / MinIO，直接解析磁盘文件。
3. **可验证可回滚** —— 导入前自动快照，失败自动还原，且还原结果可独立校验。

## 2. 能力地图

```
sse-offline-recovery/
│
├── 提取层（Extract）—— 旧盘 → 备份包        【完全离线】
│   ├── probe_oldroot.py          探查旧盘结构，产出探查报告
│   ├── pg_offline_export.py      PGDATA → CSV + schema.sql
│   ├── minio_offline_export.py   MinIO 数据目录 → 原始对象文件
│   ├── xlmeta_parse.py           xl.meta v2 解析库（可独立复用）
│   └── xlmeta_probe.py           xl.meta 结构探查/调试工具
│
├── 构建层（Package）—— 清洗 → 打包           【语义层转换在此发生】
│   ├── build_import_package.py   CSV → 单行 INSERT + 生成导入包
│   ├── transform_approver_id.py  角色名 → UUID 的可审计映射
│   ├── filter_insert_columns.py  按目标库真实列对齐
│   └── colmeta.sql               目标库列元数据（内嵌查询）
│
├── 恢复层（Restore）—— 备份包 → 新系统        【可回滚】
│   ├── import_sse_data.sh        导入（快照 + 单事务 + 自动回滚）
│   ├── verify_sse_restore.sh     独立验证（行数/checksum/关联）
│   ├── test_rollback.sh          回滚能力测试（DB 阶段）
│   └── test_rollback_minio.sh    回滚能力测试（MinIO 阶段）
│
└── 逻辑迁移层（既有）—— 在线导出/导入        【与离线层互补，不废弃】
    ├── export_sse_data.sh        运行中的系统 → 逻辑导出
    └── testdata.sql              测试夹具
```

**为什么分两层**：逻辑迁移层是"新系统恢复层"，处理运行中系统的在线导出；
离线层是"旧盘取证层"，处理磁盘级的灾难恢复。两者共用同一个导入包格式，
可以互相接力（离线提取的包 → 在线导入；在线导出的包 → 离线校验）。

## 4. 快速上手（三条命令）

### 4.1 提取（旧盘 → 备份包）

```bash
# ① 探查：先摸清旧盘结构，不要跳过
python3 tools/probe_oldroot.py --root /path/to/oldroot --out probe_report.json

# ② PostgreSQL 离线提取（需要与旧盘同 major 版本的 postgres 二进制）
python3 tools/pg_offline_export.py \
    --pgdata /path/to/oldroot/.../sse_pgdata \
    --pgbin  /path/to/postgresql/16/bin \
    --dbname sse \
    --outdir olddisk-recovered/pg-export

# ③ MinIO 离线提取
python3 tools/minio_offline_export.py \
    --datadir /path/to/oldroot/.../sse_miniodata \
    --outdir  olddisk-recovered/minio-export
```

### 4.2 打包（清洗 → 导入包）

```bash
python3 tools/build_import_package.py \
    --recovered olddisk-recovered/ \
    --outdir    olddisk-package/ \
    --schema    olddisk-recovered/pg-export/schema.sql
```

### 4.3 恢复（备份包 → 新系统）

```bash
# 导入（自动快照 + 自动回滚）
bash tools/import_sse_data.sh --from olddisk-package --target-db sse

# 独立验证
bash tools/verify_sse_restore.sh --from olddisk-package --target-db sse
```

完整参数、环境变量、宿主机无 `psql` 时的容器模式用法，见
[05-运维手册.md](docs/05-运维手册.md)。

## 7. 与 SSE 主力环境的关系

本套能力目前是**独立交付件**（`/opt/data/tools/sse-data/` + 102 共享目录），
尚未并入 SSE monorepo。并入方案见
[04-接入SSE工程方案.md](docs/04-接入SSE工程方案.md)，核心建议：

```
packages/
└── backup/          ← 新增包（建议）
    ├── src/
    │   ├── export/  ← 提取层（PG / MinIO 离线解析）
    │   ├── package/ ← 构建层（语义转换、列对齐）
    │   └── restore/ ← 恢复层（导入、验证、回滚）
    └── bin/sse-backup.ts   ← 统一 CLI 入口
```

CLI 形态设想：

```bash
sse-backup probe    --root <oldroot>
sse-backup export   --pgdata <dir> --miniodata <dir> --out <pkg>
sse-backup package  --recovered <dir> --out <pkg>
sse-backup restore  --from <pkg> --target-db sse [--dry-run]
sse-backup verify   --from <pkg> --target-db sse
```

## 8. 术语表

| 术语 | 含义 |
|---|---|
| **旧盘 / oldroot** | 出故障的磁盘挂载点，本项目实例为 `/home/szl/oldroot`（ext4 `ro`） |
| **PGDATA** | PostgreSQL 数据目录，卷名 `sse_pgdata` |
| **MinIO 数据目录** | 含 `.minio.sys` 的那一层，卷名 `sse_miniodata` |
| **xl.meta** | MinIO 每个对象的元数据文件，格式 `XL2 `（v2，msgpack 编码） |
| **备份包 / 导入包** | 本项目产出的可离线搬运目录，含 `pg/` `minio/` `meta/` `files/` |
| **语义转换** | 源数据与目标 schema 之间的语义差异修复（如角色名 → UUID） |
| **列对齐** | 按目标库**真实列**调整 INSERT 的列清单与取值 |
| **基线** | 导入前的目标状态快照，用于回滚后的等价性判定 |
| **取证层 / 恢复层** | 离线取证层（旧盘→包）、新系统恢复层（包→系统） |
