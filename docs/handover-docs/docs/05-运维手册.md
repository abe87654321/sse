## 1. 环境要求

### 1.1 提取阶段（旧盘 → 备份包）

| 组件 | 要求 | 说明 |
|---|---|---|
| Python | 3.9+ | `pg_offline_export.py` / `minio_offline_export.py` |
| `msgpack` | ≥1.0 | 仅 MinIO 提取需要 |
| PostgreSQL 二进制 | **与旧盘 major 版本一致** | 实例：16.15 |
| 磁盘空间 | ≥ 旧盘 PGDATA 的 2 倍 | 副本 + 导出产物 |
| 旧盘 | **只读挂载** | `mount -o ro` |

### 1.2 恢复阶段（备份包 → 系统）

| 组件 | 要求 | 说明 |
|---|---|---|
| `psql` / `pg_dump` / `pg_restore` | 与目标 PG major 一致 | 宿主机没有 → 用 `PG_CONTAINER` 走容器 |
| `mc` | MinIO 官方客户端 | `~/tmp/bin/mc` |
| 磁盘空间 | ≥ 备份包大小 × 2 | 快照 + 产物 |

> **ICU 说明**：PostgreSQL 单用户模式（`postgres --single`）用的是 Debian 打包的二进制，
> 链接 ICU 72；而 Ubuntu 24.04 系统自带 ICU 78，直接跑会报
> `libicui18n.so.72: cannot open shared object file`。
>
> **只在重新提取时需要解决**。只导入已构建好的包（正常运维场景），
> 全程只用 `psql` 和 `mc`，**完全不涉及 ICU**。

## 3. 日常运行

### 3.1 环境变量模板

```bash
export PG_CONTAINER=sse-postgres-1      # 走容器里的 psql/pg_dump/pg_restore
export DB_HOST=localhost
export DB_PORT=5433
export DB_NAME=sse
export DB_USER=sse
export DB_PASSWORD=<从 ~/projects/sse/.env 取真实值>
export MINIO_ENDPOINT=localhost
export MINIO_PORT=9002
export MINIO_ACCESS_KEY=<从 .env 取真实值>
export MINIO_SECRET_KEY=<从 .env 取真实值>
export SSE_DIR=~/projects/sse
export PATH=~/tmp/bin:$PATH              # 让脚本找到 mc
```

**宿主机已装 postgresql-client 时**：

```bash
unset PG_CONTAINER
# 此时直接用宿主机 psql/pg_dump/pg_restore，连接 127.0.0.1:5433
```

### 3.2 导入

```bash
cd ~/tmp/sse-offline-recovery
bash import_sse_data.sh --from olddisk-package --target-db sse
```

**先干跑**：

```bash
bash import_sse_data.sh --from olddisk-package --target-db sse --dry-run
```

**只导数据库，不导对象**：

```bash
bash import_sse_data.sh --from olddisk-package --target-db sse --skip-minio
```

**只导数据库，不动配置文件**：

```bash
bash import_sse_data.sh --from olddisk-package --target-db sse --skip-files
```

### 3.3 验证

```bash
bash verify_sse_restore.sh --from olddisk-package --target-db sse
```

**预期输出**：

```
✅ 15/15 张表行数一致
✅ 3/3 bucket 对象数一致
✅ 16/16 对象内容 checksum 一致
✅ 15/15 数据库↔MinIO 关联命中
✅ 配置文件存在
════════ 全部验证通过 ════════
```

### 3.4 回滚能力测试（建议每次升级后跑）

```bash
export MC_ALIAS=sse-import
mc alias set sse-import http://127.0.0.1:9002 minioadmin minioadmin

bash test_rollback.sh        olddisk-package sse ~/projects/sse
bash test_rollback_minio.sh  olddisk-package sse ~/projects/sse
```

> ⚠️ 这两个测试会**故意制造导入失败**，会真的操作目标库和目标 MinIO。
> **建议顺序：先跑回滚测试 → 再跑正式导入。**
> 前提：目标库已有有效基线（至少跑过一次正常导入）。

## 4. 提取（旧盘）

### 4.1 挂载旧盘为只读

```bash
# ⚠️ 务必只读挂载
mount -o ro <设备> /mnt/oldroot
mount | grep oldroot     # 确认 ro
```

### 4.2 探查

```bash
python3 tools/probe_oldroot.py --root /mnt/oldroot --out probe_report.json
```

**先读报告**，确认：
- PG major 版本（决定用哪个 `postgres` 二进制）
- 库名
- bucket 列表与对象数
- PGDATA 的确切路径

### 4.3 PostgreSQL 提取

```bash
python3 tools/pg_offline_export.py \
  --pgdata /mnt/oldroot/.../sse_pgdata \
  --pgbin  /usr/lib/postgresql/16/bin \
  --dbname sse \
  --outdir recovery/pg-export
```

### 4.4 MinIO 提取

```bash
python3 tools/minio_offline_export.py \
  --datadir /mnt/oldroot/.../sse_miniodata \
  --outdir  recovery/minio-export \
  --dry-run          # 先看会导出什么
```

### 4.5 打包

```bash
python3 tools/build_import_package.py \
  --recovered recovery/ \
  --outdir    recovery/pkg/ \
  --schema    recovery/pg-export/schema.sql
```

### 4.6 校验

```bash
cd recovery/pkg && sha256sum -c meta/checksums.sha256
```

## 5. 排障

### 5.1 排障速查表

| 症状 | 最可能原因 | 处理 |
|---|---|---|
| `pg_restore: error: input file is too short (read 0, expected 5)` | 用了 `-f` 传归档 | `-f` 是**输出**文件；归档走**位置参数** |
| `libicui18n.so.72: cannot open shared object file` | 宿主机 ICU 版本不匹配 | 只在重新提取时出现；用容器内 postgres 或解包 ICU 72 |
| `invalid input syntax for type uuid: "finance"` | 语义转换未执行 | 确认 `meta/semantic_transform.json` 存在且转换已跑 |
| `syntax error at or near "跳过"` | shell 消息混进了重定向的 SQL | 打印消息必须走 stderr |
| `integer expression expected` | `grep -c` 计数逻辑 | 已修复；见 06 文档 6.11 |
| 脚本莫名中途退出（无错误信息） | `pipefail` 把"空结果"当失败 | 已修复；见 06 文档 6.11 |
| `relation "users" does not exist` | 列对齐把表名弄错了 / 事务回滚了 | 看脚本输出的"事务已由 PostgreSQL 自动回滚"提示 |
| MinIO 对象读不出 | `storage_key` 重复拼了 bucket | 见 01 文档 6.1/6.2 |
| `docker cp` 成功但 `pg_restore` 说文件短 | 容器内路径没映射 / 文件被 `rm` 掉了 | 检查容器内路径与 `rm` 时机 |
| 回滚后表没了 | `pg_restore` 失败但回滚脚本吞掉了错误 | 看回滚输出的 ✅/❌，手动重跑 `pg_restore` |
| 验证报"表行数不一致" | 导入未完成 / 目标库有额外数据 | 确认目标库是否被其他流程写过 |

### 5.2 导入失败后的标准处置

```
① 看导入输出的最后 20 行 —— 脚本会打印 psql 的真实错误
② 确认 "事务已由 PostgreSQL 自动回滚" 出现（DB 已还原）
③ 确认 "--- 回滚 PostgreSQL ---" 段落是 ✅
④ 若回滚也是 ❌，手动还原：
     psql -c "DROP SCHEMA public CASCADE; CREATE SCHEMA public;"
     psql -c "CREATE EXTENSION IF NOT EXISTS \"uuid-ossp\"; CREATE EXTENSION IF NOT EXISTS \"pgcrypto\";"
     pg_restore -d sse --no-owner --no-privileges --clean --if-exists <备份>/backup.dump
⑤ 备份目录在 .rollback-<时间戳>/，**不要删**
```

### 5.3 查看备份目录

```bash
ls -la olddisk-package/.rollback-*/          # 所有历史快照
cat olddisk-package/.rollback-*/meta/…       # 快照元信息
```

## 7. 安全须知

### 7.1 凭据处理

| 位置 | 内容 | 建议 |
|---|---|---|
| 备份包 `files/ai-config.json` | 真实 `mineruToken` | 分发前脱敏，或走加密通道 |
| 备份包 `files/env.local` | 邮箱密码、阿里云 AK/SK、JWT、MCP key | 同上；**绝不进共享盘** |
| 脚本默认 `DB_PASSWORD` / `MINIO_SECRET_KEY` | 开发环境默认值 | 生产环境必须用环境变量覆盖 |
| SSH/sudo 密码 | 经 `SSH_ASKPASS` 临时注入 | 不落盘，用完即删 |

**已发生的暴露**：当前 102 共享目录里的 `olddisk-package/files/` 含上述真实凭据。
若要清理，需先确认没人正在用该目录。

### 7.2 旧盘安全

- 旧盘**必须只读挂载**
- `postgres --single` 只在**副本**上跑
- 提取结束后核验原 PGDATA 文件未被修改

```bash
# 核验原盘零修改（提取前后各跑一次对比）
find /mnt/oldroot/.../sse_pgdata -type f -newermt "提取开始时间" | head
# 预期：无输出
```

### 7.3 权限

- 备份包可能含敏感信息 → 目录权限 `700`
- 恢复目标库前确认是**预期环境**（别在生产库上跑演练）
