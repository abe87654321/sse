## 1. 环境变量

```bash
# PostgreSQL
DB_HOST=localhost
DB_PORT=5433
DB_NAME=sse
DB_USER=sse
DB_PASSWORD=***

# MinIO
MINIO_ENDPOINT=localhost
MINIO_PORT=9002
MINIO_ACCESS_KEY=minioadmin
MINIO_SECRET_KEY=minioadmin
MINIO_BUCKETS=invoices,payment-receipts,avatars

# 备份
BACKUP_DIR=./backups
MINIO_BACKUP_BUCKET=backups
MINIO_BACKUP_PREFIX=sse/

# API 恢复开关（默认关闭）
BACKUP_RESTORE_ENABLED=true
```

恢复使用同一套 DB 凭据连接 `postgres` 库创建演练库，执行账号需要 `CREATEDB` 权限。

## 3. CLI

### 3.1 创建备份

```bash
# 本地
pnpm sse-backup create --out /data/sse-backups

# 本地 + 上传 MinIO
pnpm sse-backup create --out /data/sse-backups --upload

# 包含 .env（敏感）
pnpm sse-backup create --out /data/sse-backups --include-secrets
```

产物：

```
/data/sse-backups/<backupId>/
├── package/manifest.json
├── package/db/*.jsonl
├── package/minio/...
├── package/files/...
├── package/meta/checksums.sha256
└── <backupId>.tar.gz
```

### 3.2 列表与校验

```bash
pnpm sse-backup list --out /data/sse-backups
pnpm sse-backup verify --from <backupId> --out /data/sse-backups
```

校验会重新读取包内文件、重算 checksum、核对行数与 manifest。失败退出码为 3。

### 3.3 恢复到演练库

```bash
pnpm sse-backup restore \
  --from <backupId> \
  --target-db sse_drill_<backupId> \
  --target-minio-prefix drills/<backupId>/ \
  --out /data/sse-backups
```

说明：

- 目标库必须**不存在**；已存在会失败。
- 目标库名不能等于当前 `DB_NAME`。
- MinIO 对象写入 `drills/<backupId>/` 前缀，不动当前对象。
- 配置文件落到 `/data/sse-backups/restores/<restoreId>/files/`。
- 恢复成功后写入 `/data/sse-backups/restores/<restoreId>.json`。

### 3.4 演练记录与一键清除

```bash
pnpm sse-backup drills --out /data/sse-backups

pnpm sse-backup drill:clean \
  --target-db sse_drill_<backupId> \
  --target-minio-prefix drills/<backupId>/ \
  --restore-id <restoreId> \
  --confirm "CLEANUP sse_drill_<backupId>" \
  --out /data/sse-backups
```

清除动作：

1. `DROP DATABASE IF EXISTS "<targetDb>" WITH (FORCE)`；
2. 删除目标 bucket 下该前缀的对象；
3. 将演练记录标记为 `deleted`。

## 4. 管理端

入口：`/admin/backups`（仅 admin）。

- 创建备份：可选“包含 .env”“上传到 MinIO”。
- 下载：下载 `<backupId>.tar.gz`。
- 校验：启动校验任务。
- 上传：把本地备份补传到 MinIO。
- 恢复：填写目标库、MinIO 前缀、确认短语 `RESTORE <backupId>`。
- 演练库：列表显示记录，点击“清除”，输入 `CLEANUP <targetDb>`。

API 恢复/清除必须设置 `BACKUP_RESTORE_ENABLED=true`。

### 4.1 API

```http
POST /admin/backups
GET  /admin/backups?location=local|minio
GET  /admin/backups/jobs/:jobId
GET  /admin/backups/:id/download
POST /admin/backups/:id/verify
POST /admin/backups/:id/upload
POST /admin/backups/:id/restore
GET  /admin/backups/drills
POST /admin/backups/drills/:restoreId/cleanup
DELETE /admin/backups/:id
```

恢复 body：

```json
{
  "targetDb": "sse_drill_b1",
  "targetMinioPrefix": "drills/b1/",
  "dryRun": false,
  "confirm": "RESTORE b1"
}
```

清除 body：

```json
{
  "targetDb": "sse_drill_b1",
  "targetMinioPrefix": "drills/b1/",
  "confirm": "CLEANUP sse_drill_b1"
}
```

在“统计分析”页，finance/admin 可见 Excel / CSV / JSON 按钮。

```http
GET /statistics/export?format=xlsx
```

- JSON：嵌套结构。
- 每次导出写 `audit_events`（action=`statistics.export`）。

## 6. 测试机真实演练（部署前必做）

```bash
# 1. 正常备份
pnpm sse-backup create --out /data/sse-backups

# 2. 校验
pnpm sse-backup verify --from <id> --out /data/sse-backups

# 3. 恢复演练库
pnpm sse-backup restore --from <id> --target-db sse_drill_<id> --out /data/sse-backups

# 4. 查看演练记录
pnpm sse-backup drills --out /data/sse-backups

# 5. 一键清除
pnpm sse-backup drill:clean --target-db sse_drill_<id> \
  --confirm "CLEANUP sse_drill_<id>" --restore-id <restoreId> --out /data/sse-backups

# 6. 再次恢复，确认可重复
pnpm sse-backup restore --from <id> --target-db sse_drill_<id> --out /data/sse-backups
```

验收点：

- 备份包 checksum 全绿。
- 演练库表行数与 manifest 一致。
- 演练前缀对象数与 SHA-256 一致。
- `storage_key` / `avatar_url` 关联校验全部命中。
- 篡改备份文件后 `verify` 失败。
- 清除后演练库不存在、前缀对象为 0、记录为 `deleted`。
- 连续两轮“恢复 → 清除”成功。

## 7. 安全注意事项

1. 不要在生产库上执行恢复；v1 只写新建演练库。
2. 不要清空 MinIO 前缀为空；API/CLI 默认要求非空前缀。
3. `.env` 默认不备份；`--include-secrets` 生成的包属于敏感数据，权限设为 `700`。
4. 恢复开关 `BACKUP_RESTORE_ENABLED` 只在演练/迁移窗口开启。
5. 所有备份/恢复/下载/删除/清除动作写入 `audit_events`，便于追溯。
